## 3. MP3 播放数据流（SD → PSRAM → SRAM → I2S → 耳朵）

```text
时间线 →

┌─────────┐    ┌─────────────┐    ┌──────────────┐    ┌─────────────┐    ┌────────┐
│ SD 卡   │    │ SRAM        │    │ PSRAM        │    │ SRAM        │    │ 扬声器  │
│         │    │ SD DMA Buf  │    │ MP3 ReadBuf  │    │ I2S DMA Buf │    │        │
│ song.mp3│    │ 16KB        │    │ 128KB        │    │ 32KB        │    │ 🔊     │
└───┬─────┘    └──────┬──────┘    └──────┬───────┘    └──────┬──────┘    └───┬────┘
    │                │                  │                   │               │
    │  ① SDMMC+DMA  │                  │                   │               │
    │  读一个块      │                  │                   │               │
    ├───────────────→│                  │                   │               │
    │                │  ② CPU copy     │                   │               │
    │                │  (不通过DMA)     │                   │               │
    │                ├─────────────────→│                   │               │
    │                │                  │  ③ CPU 解码MP3   │               │
    │                │                  │  madlib/helix    │               │
    │                │                  │  MP3→PCM         │               │
    │                │                  │                   │               │
    │                │                  │  ┌── PCM RingBuf │               │
    │                │                  │  │  256KB        │               │
    │                │                  │  │               │               │
    │                │                  │  │  ④ CPU copy   │               │
    │                │                  │  │  分块搬        │               │
    │                │                  │  └──────────────→│               │
    │                │                  │                   │               │
    │                │                  │                   │ ⑤ I2S+DMA   │
    │                │                  │                   │ 持续输出      │
    │                │                  │                   ├──────────────→│
    │                │                  │                   │               │
    │                │                  │   循环①~⑤         │               │
    │                │                  │   直到歌曲结束     │               │
    │                │                  │                   │               │


关键点：
  DMA 只参与 ①(SD→SRAM) 和 ⑤(SRAM→I2S) 两步，即只搬硬件端的数据
  CPU 负责 ②③④ 三步：拷数据、解码、喂缓冲
  PSRAM 是 CPU 的工作区，DMA 不直接访问 PSRAM
  SRAM 是 DMA 的出入口，所有要搬的数据必须先在 SRAM 里
```

## 4. GIF/UI 显示流（Flash → PSRAM → SRAM → LCD → 眼睛）

```text
┌─────────┐    ┌─────────────┐    ┌──────────────┐    ┌─────────────┐
│ Flash   │    │ PSRAM       │    │ SRAM         │    │ LCD 屏幕    │
│ assets  │    │ GIF文件缓存  │    │ LCD DMA BufA │    │ 368×448     │
│ ui.gif  │    │ 128KB       │    │ 26KB         │    │             │
└───┬─────┘    └──────┬──────┘    └──────┬───────┘    └──────┬──────┘
    │                │                  │                   │
    │ ① CPU 读Flash │                  │                   │
    │ 或 mmap       │                  │                   │
    ├───────────────→│                  │                   │
    │                │  ② CPU GIF解码  │                   │
    │                │  LZW解压        │                   │
    │                │  →RGB565帧      │                   │
    │                │                 │                   │
    │                │  ③ CPU copy    │                   │
    │                │  分块拷         │                   │
    │                ├────────────────→│                   │
    │                │                 │  ④ QSPI+DMA      │
    │                │                 │  局部刷屏         │
    │                │                 ├──────────────────→│
    │                │                 │                   │
    │                │  ┌──────┐       │                   │
    │                │  │ BufB │       │                   │
    │                │  │ 26KB │       │                   │
    │                │  └──┬───┘       │                   │
    │                │     │           │                   │
    │                │     └──────────→│  A/B交替          │
    │                │       ③' copy   │  一块DMA传输中     │
    │                │                 │  一块CPU填充中     │


关键点：
  GIF 放 Flash 不占 SD 带宽 → 音频和UI并行不抢总线
  DMA 只参与 ④(SRAM→LCD) 这一步
  CPU 做 ①②③：读文件、解码GIF、拷到DMA缓冲
  双缓冲 A/B 让 DMA 传输和 CPU 填充可同时进行
```

## 5. I2C 控制流（CPU ↔ 各器件，低速命令通道）

```text
                              ┌──────────┐
                              │   CPU    │
                              │          │
                              │ 初始化顺序│
                              │ 读写寄存器│
                              │ 轮询状态 │
                              └────┬─────┘
                                   │
                        I2C 总线 (GPIO14=SCL, GPIO15=SDA)
                        400kHz，共享，无 DMA
                                   │
            ┌──────────┬───────────┼──────────┬───────────┬──────────┐
            │          │           │          │           │          │
            ▼          ▼           ▼          ▼           ▼          ▼
       ┌────────┐┌────────┐┌──────────┐┌────────┐┌────────┐┌──────────┐
       │FT3168  ││PCF85063││IO扩展器  ││AXP2101 ││QMI8658 ││ES8311    │
       │0x38    ││0x51    ││0x20      ││0x34    ││0x6B    ││0x18      │
       │        ││        ││          ││        ││        ││          │
       │触摸坐标││实时时钟││LCD_RST   ││电池电量││加速度  ││Codec配置 │
       │INT→GP21││        ││TP_RST    ││充电状态││角速度  ││音量/采样 │
       │        ││        ││DSI_PWR_EN││电源管理││        ││          │
       │        ││        ││SD_CS     ││        ││        ││          │
       └────────┘└────────┘└──────────┘└────────┘└────────┘└──────────┘
            
            数据量: 每个坐标 4~6 字节
            速度:   400kHz I2C ≈ 几十 KB/s
            DMA:    不需要，数据太小 DMA 开销不划算
            方式:   CPU 直接读写 I2C 寄存器


关键点：
  I2C 不走 DMA，数据量太小（触摸坐标几个字节），CPU 直接读写即可
  I2C 初始化顺序至关重要：先 IO 扩展器 → 再放开屏和触摸复位 → 再初始化和读取
  FT3168 的 INT 脚(GPIO21)用于唤醒 TouchTask，不是轮询
  其他器件(IMU/RTC/PMU)低优先级轮询即可
```

## 6. 对比：DMA 参与 vs 不参与的路径

```text

   有 DMA 的路径（连续大数据，KB~MB 级别）：
   ═══════════════════════════════════════

      SD 卡 ═══ SDMMC DMA ═══→ SRAM        （读文件块，8~16KB/次）
      SRAM  ═══ I2S DMA   ═══→ I2S 总线     （放音频，连续输出）
      SRAM  ═══ QSPI DMA  ═══→ LCD 面板     （刷屏幕，26KB/半帧）


   没有 DMA 的路径（小数据或计算密集）：
   ═══════════════════════════════════════

      I2C  ←──→ CPU 直接读写寄存器          （坐标/配置，几个字节）
      GPIO ←── CPU 读电平                   （按键，1 bit）
      PSRAM ←──→ CPU copy                  （大数据中转，不直接连外设）


   原因一句话：
   ───────────
   DMA 适合"我知道源和目标、知道长度、连续传输"的场景
   DMA 不适合"随机读写、小数据、需要计算"的场景
   DMA 无法访问 PSRAM → 所有外设 DMA 都要经过 SRAM
```
