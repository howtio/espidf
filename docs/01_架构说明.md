# 架构说明

> 双核 FreeRTOS 多任务架构。App FSM 为唯一决策中枢，模块间只通过 Queue 通信。
> USB Serial 是全系统调试出口，SystemMonitor 负责状态采集和日志输出。

---

## 1. 总体架构

```text
┌── ESP32-S3 双核 ─────────────────────────────────────────────────┐
│                                                                   │
│  Core 0 (音频优先)              Core 1 (UI + 交互 + 监控)         │
│  ┌─────────────────┐           ┌──────────────────┐              │
│  │ AudioTask        │           │ AppTask           │              │
│  │ (最高优先级)      │           │ (中高优先级)       │              │
│  │                  │  Queue    │                   │              │
│  │ 读 MP3 → 解码    │◄────────►│ App FSM 状态机     │              │
│  │ → PCM → I2S DMA  │           │ 事件→决策→分发    │              │
│  │ 水位监控         │           └────────┬──────────┘              │
│  └─────────────────┘                    │                         │
│                                         │                         │
│  ┌─────────────────┐           ┌────────┴──────────┐              │
│  │ LogTask          │           │ UiTask             │              │
│  │ (最低优先级)      │           │ (中优先级)          │              │
│  │                  │           │                    │              │
│  │ SystemMonitor    │           │ LVGL 渲染          │              │
│  │ 每5秒采集+打印:   │           │ GIF 解码+帧率控制  │              │
│  │ 电池/内存/PCM    │           │ 状态栏+进度条+按钮 │              │
│  │ 水位/GIF帧率     │           └────────┬───────────┘              │
│  └─────────────────┘                    │                          │
│                                         │                          │
│                                ┌────────┴───────────┐              │
│                                │ TouchTask           │              │

│                                │ (中低优先级)         │              │
│                                └────────────────────┘              │
│                                                                   │

│  │ GIF 文件缓存 128KB│          │ SD DMA Buffer 16KB │           │
│  │ LVGL 帧缓冲 322KB │          │ 任务栈+Queue 80KB  │           │
│  │ UI 对象 ~500KB    │          │ 系统保留 ~100KB    │           │
│  └───────────────────┘          └────────────────────┘           │
```

## 2. FreeRTOS 任务分配

| 任务 | 优先级 | 核心 | 栈 | 职责 |
|------|--------|------|-----|------|
| `AudioTask` | 最高 (5) | Core 0 | 8KB | MP3 解码 + PCM 输出 + 水位监控 |
| `AppTask` | 中高 (3) | Core 1 | 8KB | App FSM 状态机 + 事件分发 |
| `UiTask` | 中 (2) | Core 1 | 8KB | LVGL + GIF 解码 + 状态栏 |
| `TouchTask` | 中低 (1) | Core 1 | 4KB | I2C 读触摸坐标 → 事件入队 |
| `ButtonTask` | 中低 (1) | Core 1 | 4KB | GPIO 消抖 → 事件入队 |
| `LogTask` | 最低 (0) | 任意 | 4KB | SystemMonitor: 每 5s 采集/打印 |

## 3. Queue 设计

### AppEventQueue（输入事件 → App FSM）

| 事件 | 来源 | 含义 |
|------|------|------|
| `TouchPlayPause` | TouchManager | 点播放/暂停 |
| `TouchNext` | TouchManager | 下一首 |
| `TouchPrev` | TouchManager | 上一首 |
| `ButtonPlayPause` | ButtonManager | BOOT 键 |
| `AudioEnd` | AudioPlayer | 歌曲播完 |
| `SdRemoved` | StorageManager | SD 拔出 |
| `SdInserted` | StorageManager | SD 插入 |
| `DecodeError` | AudioPlayer | 解码失败 |
| `LowMemory` | MemoryPool | 内存告警 |

16~32 容量

### AudioCommandQueue（App FSM → AudioPlayer）

| 命令 | 参数 |
|------|------|
| `PlayFile` | path |
| `Pause` | — |
| `Resume` | — |
| `Stop` | — |
| `Next` | — |
| `Prev` | — |
| `SetVolume` | 0~100 |

8~16 容量

### UiEventQueue（App FSM + SystemMonitor → UiTask）

| 事件 | 参数 | 来源 |
|------|------|------|
| `SetPlayState` | playing/paused/stopped | FSM |
| `SetSongName` | string | FSM |
| `UpdateProgress` | current, total | FSM |
| `SetGifLevel` | full/reduced/minimal | FSM |
| `ShowError` | code, msg | FSM |
| `UpdateStatusBar` | 🆕 SystemStatus | SystemMonitor |

8~16 容量

## 4. 状态机

```text
                    ┌──────────┐
                    │   BOOT   │
                    └────┬─────┘
                         │ 打印启动全景 (SystemMonitor)
                         ▼
                    ┌──────────┐
               ┌───→│ SCAN_SD  │←──────────────┐
               │    └────┬─────┘               │
               │         │ SD 就绪 + 歌曲列表    │
               │         ▼                     │
               │    ┌──────────┐               │
               │    │   IDLE   │←──────────────┤
               │    └────┬─────┘               │
               │         │ PlayFile            │
               │         ▼                     │
               │    ┌──────────┐               │
               │    │ PLAYING  │──→ PAUSE ──→  │
               │    │          │    ↓           │
               │    │ 自动下一首 │  PAUSED ──→  │
               │    │ AudioEnd  │    Resume     │
               │    └────┬─────┘               │
               │         │ Next/Prev           │
               │         ▼                     │
               │    ┌──────────────┐           │
               │    │ NEXT_LOADING │───────────┘
               │    │ 清缓冲→开新歌  │
               │    │ 预填→PLAYING  │
               │    └──────────────┘
               │
               └───── ERROR ←── SD_REMOVED / DECODE_ERROR / LOW_MEMORY
                      │
                      └── 恢复条件满足 → SCAN_SD

每个状态变更 → 串口打印：
  [INF] [FSM  ] 状态: IDLE → PLAYING (TouchPlayPause)
```

## 6. 调试日志架构

```text
所有模块 ──→ SystemMonitor::log() ──→ ESP_LOGD/I/W/E ──→ USB Serial
                                                          │
                                            idf.py monitor │
                                                          ▼
                                                   Claude 调试终端

日志等级:
  TRACE — 函数进入/退出、每帧细节   (生产环境关闭)
  DEBUG — 水位/帧率/内存周期打印     (生产环境关闭)
  INFO  — 状态变更、初始化结果      (生产环境保留)
  WARN  — 降级触发、水位告警        (生产环境保留)
  ERROR — 硬件错误、解码失败        (生产环境保留)
```

## 7. 分层原则

```
1. App FSM 是唯一决策者 — 所有状态变更都经 App FSM
2. 模块间只通过 Queue 通信 — 不直接调对方 public 方法
3. 硬件抽象在 Manager 层 — 业务逻辑不碰 GPIO/I2C/I2S 寄存器
4. 音频永不断 — PCM RingBuffer 低于 30% 时 GIF/UI 降级
5. PSRAM 存大对象，SRAM 存 DMA 缓冲 — 不混用
6. 启动时一次性分配 — 运行时不 malloc/free
7. 串口即眼睛 — 每个模块初始化/状态变更/异常都打日志，Claude 靠串口调试
```
